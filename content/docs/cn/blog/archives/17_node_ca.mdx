# 适用范围

一般来说, 只要你看见报错内容是 `unable to verify the first certificate`, 要么是隔壁熊孩子给你的电脑调到了 2099 年, 要么就是你的加速器的问题()

问题全出在 Node.js 上面😇

# 解决方案

解决问题挺简单的()

## 导出证书

首先打开**钥匙串访问**应用.

<Callout type="info" title="找不到钥匙串访问应用?">
    新的 macOS 中, 钥匙串访问可能在启动台中找不到 (包括第三方启动台, 不过在 macOS 26+ 的 App 中搜索**钥匙串访问**还是可以找到的.), 此时需要直接在访达中寻找.

    跳转到 `/System/Library/CoreServices/Applications`, 你应该能看见这个应用.

    启动时, 可能会推荐你到新的密码 App 管理密码, 由于我们要拿的是证书, 直接打开钥匙串访问.
</Callout>

在右上角的搜索框中搜索证书的名字. (一般来说和加速器的名称差不多, 比如 Steamcommunity 的证书叫 Steamcommunity302, Watt Toolkit 的证书叫 SteamTools Certificate)

右键证书, 点击**导出 "\<证书名称\>"...**.

将文件格式更改为**增强保密邮件(pem)**, 也就是以 .pem 后缀结尾的文件.

选择一个地方存储导出的证书.

<Callout type="warn" title="选择一个你不会动的位置">
    设置完成后, 每次启动 Node.js 或 Node.js 应用, 所以在确定位置后, 不要重命名, 删除或移动文件或上层文件夹, 否则设置将失效.
</Callout>

## 信任证书

打开终端, 输入 `cd `(注意带上空格), 将下载文件夹拖入终端中.

或者在下载文件夹中, 右键访达下方的路径中的下载文件夹, 点击**在终端中打开**.

然后, 在终端中输入:

```zsh tab="如果你用的是 GUI 应用就输入这个"
launchctl setenv NODE_EXTRA_CA_CERTS "<你的证书所在位置的路径>"
```

```zsh tab="如果你用的是 CLI 应用或者在调试 Node.js 就输入这个"
echo 'export NODE_EXTRA_CA_CERTS="<你的证书所在位置的路径>"' >> ~/.zshrc``

# 就是在你用户目录下的 .zshrc 加了一行叫 export NODE_EXTRA_CA_CERTS="<你的证书所在位置的路径>" 的字, 由于是直接添加, 如果多次重复添加的话并不会被覆盖, 而是会重复(别想了就算添加多个也只能信任一个的), 建议自己去 .zshrc 文件里面改.
```

这将设置一个用户的环境变量, 指示 Node.js 可以信任哪个证书.

<Callout type="warn" title="无法信任多个证书">
    如果你要交替着用加速器(真的假的), 需要同时信任多个证书, 就不能用上面那个方法了()

    NODE_EXTRA_CA_CERTS 一次只能存一个证书的路径, 如果你先信任了一个证书, 再运行一次命令信任别的证书, 那么前面的证书路径就会被删掉, 变成后面的证书路径. (使用第二种方法添加的除外, 但最终也只会使用其中一个的证书路径)

    当然, 据 Qwen 所说, 解决方案是将多个证书文件合并为一个 .pem 文件, 然后再进行设置.

    但由于没时间验证, 具体方法只能大家自己从网上搜啦 XD
</Callout>

现在, **彻底重启**任何因为证书报错导致不能用的应用, 现在应该就没有任何问题啦~

享受吧 (≧▽≦)

# 删除环境变量

应该不会有人想这么做吧, 删了之后 Node.js 又不信你的证书了()
当然要是你想删的话, 直接用 `launchctl unsetenv NODE_EXTRA_CA_CERTS` 命令就可以删了, 同时证书文件也能动能删啦 x)
